# Test card 2.11.3: siege engine MaxCount in multiplayer (GitLab #2, FWP-E-01)

Needs two PCs (PC-A hosts, PC-B joins), both with the same Crusader DE Tweaker build (same version and DLL SHA-256)
and the same Script Extender. Record both versions and hashes before the match.

Setup (PC-A only): Units file `[CHIMP_TYPE_CATAPULT] MaxCount = 2`. Lobby tab: "Players who join use my configs" ON.

1. Start a 2-player skirmish (both human). Both players: build an Engineer's Guild, enough gold.
2. PC-A player: place 2 Catapult tents. Expected: both accepted. Place a 3rd while the first 2 are still tents.
   Expected: placement refused (blocked cursor), no gold spent.
3. PC-B player: the same. Expected: the same (PC-B uses the host's file).
4. Wait until all 4 Catapults are out. Optional: with DebugLogging on, a 3rd Catapult forced by another route
   (for example a save made before the cap) is removed on BOTH PCs; the log line `[UnitCaps] CHIMP_TYPE_CATAPULT cap
   reached (2). Removed unit id=...` appears on both with the same id.
5. Play 10 minutes with the Catapults firing. Expected: no out-of-sync message; both PCs show 2 Catapults per player.
6. Repeat once with sync OFF and only PC-B's own file at MaxCount 2. Expected: PC-B's 3rd tent is refused on PC-B;
   nothing is removed on either PC after spawn; log on both: `multiplayer match, so MaxCount 2 from your own Units
   file does not remove spawned units` (PC-B only, since PC-A has no cap). No desync.

PASS = steps 2, 3, 5 and 6 as expected and no desync. Attach both LogOutput.log files (grep `[UnitCaps]`, `[ConfigSync]`).
Single-player check: a 3rd Catapult tent is refused; nothing else changes.
